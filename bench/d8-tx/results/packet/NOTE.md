# U7 one-packet RF gate: verdict PASS (batch 1, 2412000 kHz, 10 PKT sent)

Steps (owner bench, user toggled E8):
1. STM: SHA256SUMS of out/4bdc8581 verified (`stm_checksum_verify.txt`); entered DFU with CLI `bl` (the `dfu` CLI command does not exist, first try in `dfu_enter.txt`), `dfu-util -a 0 -s 0x08000000:leave -D <bin 06e88ff2...>` rc 0 (`dfu_flash.txt`); `version`/`rxdiag info` show fw=4bdc8581 (`postflash_identities.txt`). ESP: current d8tone.bin sha256 3698ae6f... (differs from the U4 image a62d6c24..., rebuilt), app-only write at 0x10000, hash verified (`esp_flash.log`, `esp_hashes.txt`); PING `P,d8tone,1`, STAT keyed=0 (`esp_idle.txt`).
2. Source-off (E8 OFF), `rxdiag pkt`: NOT zero P records. 2421032 5 s: 2 P (19 B and 2 B, crc_ok=0, rssi=lqi=0, EPART); 2412000: two 5 s runs, 4+6 P, all crc_ok=0 short/random fragments (`source_off_*.txt`). Noise, none CRC-valid, none starting 11 42 B2. Later 2412000 3 s recheck before ESP test: 0 P (`source_off_recheck_2412000.txt`).
3. E8 control ON at 2421032 20 s: 77 P records, 32 crc_ok=1 packets `11 42 B2 00 xx 01 ...` (18 B, rssi~75 lqi~46) (`control_e8_2421032.txt`). Control PASS; no retry needed. E8 then turned OFF.
4. ESP test, receiver 2412000, batch 1 only, power 127, vector = d8_vectors.build(0) body `1142b2000001cacacaca8888cacacaca8888` (CRC afa7 appended by firmware): 10/10 PKT replies OK, all K,pkt: bits=208 on_us 6700-6704, max_late_ns=1266, late_bits=207, b8_off bit18 clear, STAT keyed=0 after, no reboot (`batch1_2412000_esp.txt`, `esp_runner_log.jsonl`). Receiver: 7 P records crc_ok=1 (rssi 11-13, lqi 51) whose bytes equal the vector body exactly; 2 more equal body but crc_ok=0 with rssi=lqi=0 followed by a 2-byte stray P (same split artifact the real E8 shows in control); 1 PKT with no full record; plus noise fragments (`analysis_batch1.txt`, `batch1_2412000_stm.txt`). Batches 2/3 not needed. Total PKT sent: 10 (<=30).

Caveat: rxdiag P records are 18 bytes (length+17 payload); the CC2500 strips the CRC bytes (hardware CRC_OK flag carries the result), identically for E8 packets. `compare_p_to_vector` demands 20 bytes, so it reports "len 18 want 20, crc bytes missing" for every packet even on matches: it needs a fix to compare 18 B + crc_ok (outside U7 scope). Comparison here was done on the 18-byte body + crc_ok=1. late_bits=207 of 208 with max_late_ns 1266 is far below a bit time (~32 us) but note it.
Caveat: radiated ESP packet at power 127 received within bench range; no distance/attenuation info.
`pk.py` is the helper that ran steps 2-4.
